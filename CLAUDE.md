## crates/ — the Rust workspace (Rust CLI workspace plan output)

- Root `Cargo.toml` is the workspace; members are `crates/dml-core`, `crates/dml-wow`, `crates/dml-wow-cli`, `launcher/src-tauri`. `Cargo.lock` lives at the repo root, and so does `target/`.
- `dml-core` — game-agnostic: envelope/events/error, `DmlRunner`, `proc` (bounded/streamed subprocess), `conf` (byte-parity `Key = value` engine), `engine` + `compose` (docker), `backend`, `util` (`~/.dml`). **Must never depend on tauri.** "No tokio" is aspirational only — reqwest's blocking feature pulls it transitively.
- `dml-wow` — the WoW library (~30 modules) + all **18** `tests/*_parity.rs` suites. Config/tuning/module registries are `include_str!`-embedded from `crates/dml-wow/data/` (config 66 rows, tuning 13, catalog cpp 19 / lua 9 / sql 10), so the native path no longer shells the bash CLI for them — regenerate them from the bash oracle if `cli/` changes.
- `dml-wow-cli` — clap 4 binary named `dml-wow`, 74 subcommands, same envelope/NDJSON contract as bash `dml --json`. Only new external dep in the whole plan: clap.
- **Contract docs (keep in sync when the CLI surface changes): `docs/cli-contract.md`** (envelopes, NDJSON vocabulary, exit codes, full command table, env vars, caveats) and `docs/rust-cli-pitch.md`.
- Dev loop from the repo root: `cargo test --workspace`; CLI smoke `cargo run -p dml-wow-cli -- version`. CI is `.github/workflows/rust.yml` (windows = whole workspace, ubuntu = the three crates).
- **Test-portability rules, learned the hard way:** never hardcode `cmd.exe` or a drive-letter `Path` literal in a test — use a per-platform `#[cfg]` helper (the convention lives in `dml-core`'s `runner.rs`/`proc.rs` and `dml-wow`'s `backup.rs`/`restore.rs`). `std::env::join_paths` rejects a component containing the platform's PATH separator, so `C:\...` entries fail on Unix. Forward-slash path literals work on BOTH flavours; backslash ones are Windows-only.
- **The vacuous-pass trap:** `cargo test` captures `eprintln!` from PASSING tests, so a suite that skips for a BROKEN reason looks identical to one that ran. That is why the Linux CI job runs with `-- --nocapture`, and why every parity suite's `find_bash`/`yq_path` gate is per-platform. When a test's assertion could be satisfied by an early error return, assert something a failed spawn cannot satisfy (e.g. elapsed >= the deadline).
- **List order is NOT contractual:** bash `sort(1)` collates per locale (en_US = case-insensitive), Rust `Vec::sort` is byte order. Compare file sets, not positions.
- Live parity gate (needs the snapshot server at `C:\Users\perzi\dml-native` running): `$env:DML_GAMES_DIR="C:\Users\perzi\dml-native"; $env:DML_YQ_BIN="C:\Users\perzi\dml-native\tools\yq.exe"; cargo test -p dml-wow --tests -- --nocapture` → all 18 suites must run with **zero SKIP lines** (686 passed 2026-07-27).

- `cli/dml` is a **committed build artifact**: `bash cli/build.sh` concatenates `cli/src/*.sh` in glob order (00-head, 10-json, 20-soap, 30-db, 90-main). NEVER edit `cli/dml` directly; edit `cli/src/*.sh` and rebuild.
- `dml wow` namespace (Plan 3): `soap-setup`, `soap-exec`, `items search`, `mail-item`, `teleport`/`teleport-list`, `characters`/`paperdoll`, `gm level/gold/heal/revive/summon`, `bridge-setup` (party-setup = alias, deploys lua/party+lua/gm), `party botcmd` (closed gear/talents/maintain whisper allowlist), `party preset-save/list/delete/load` (`~/.dml/party-presets`, one class per line, load = replace + streamed), `backup create/list/delete/restore` (`~/.dml/backups`, newest-10) — documented in `cli/README.md` "wow subcommands". Security posture: SOAP host-published on 127.0.0.1:7878 only (pinned via the title's `.env` `DOCKER_SOAP_EXTERNAL_PORT` — base compose already publishes the port; never add a second `ports:` entry, Compose concatenates lists); SOAP calls flock-serialized (`~/.dml/soap.lock`); MySQL access strictly read-only (mutations via SOAP GM commands only) — ONE exception for character data: `wow backup restore` imports a snapshot via mysql, only with world+auth stopped and always behind an automatic -prerestore safety dump (the LAN toggle's realmlist UPDATE is the only other write); creds via `DML_SOAP_URL/USER/PASS` env (default admin/admin).
- Sanitization invariants (tested; keep them): `_xml_escape` escapes `&` FIRST; `sql_escape` escapes `\` then `'`; SOAP-bound free text strips `"`/CR/LF (AC #2695 second-command surface); numeric values are `^[0-9]+$`-whitelisted before SQL splice; every value-taking flag calls `_need_flag_val` before reading `$2` (else `set -u` aborts with no JSON envelope).
- bash while-read loops fed from command substitution need `|| [[ -n "$var" ]]` (trailing-newline strip silently drops the last row otherwise) — see `_items_rows_to_json`.
- Runs inside WSL2 distro `dml-arch` as user `dml`; games in `$HOME/games` (override for tests: `DML_GAMES_DIR`). Repo inside WSL: `/mnt/c/Users/perzi/dads-mmo-lab`.

## Gotchas

- **Line endings:** bash inside WSL chokes on CRLF. `.gitattributes` forces LF for `*.sh`, `*.bats`, `*.bash`, and `cli/dml`; keep new shell files LF.
- **PowerShell 5.1 + UTF-8:** BOM-less `.ps1` files containing non-ASCII (em dashes) mis-parse under the ANSI codepage. `cli/tests/windows-smoke.ps1` carries a UTF-8 BOM on purpose; keep BOMs on any non-ASCII `.ps1`.
- **Rust toolchain PATH:** Rust 1.97 MSVC is installed per-user but `%USERPROFILE%\.cargo\bin` may be missing from a fresh Claude shell's PATH — use the full path or prepend it per call. MSVC Build Tools 2022 (C++ workload) and Node 22 are installed; WebView2 present.
- **Build memory:** `.cargo/config.toml` pins `build.jobs = 8` and the root `Cargo.toml` sets `[profile.dev] debug = "line-tables-only"` (deps: none). Uncapped, cargo fans out to the logical CPU count (32 here) and each `link.exe` holds 0.5–1.2 GB, pinning RAM at 100% on a 31 GB box that also reserves 16 GB for WSL2. Don't run `cargo run` (tauri dev) and `cargo test --workspace` at the same time — same `target/` lock, double the peak. Changing either setting forces one full rebuild.
- The `games` namespace is JSON-first: `games list`/`status` always emit JSON; only `games start|stop|restart` have a text mode. Legacy top-level commands (`list`, `status`, `start`, …) keep their exact text output — the old C# tray parses it.
- `dml-start.sh` hook: `games start|restart` run `<compose_dir>/dml-start.sh <mode>` when present+executable (avoids re-running ac-db-import on restarts).
