# My Party Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the disabled Playerbots sidebar page on: a logged-in player builds a party of playerbots from the DML Launcher — add a bot by class, see the party, kick a bot, re-summon after a relog — via SOAP → Eluna bridge scripts → `.playerbots bot addclass` in the player's own session.

**Architecture:** Three AGPL Lua bridge scripts (reimplemented from the Lab reference scripts on this box) deploy to the server's Eluna dir and run playerbot commands in the online player's session. New `dml wow party` CLI verbs drive them over the existing SOAP transport, confirm joins by polling `group_member` (MySQL, read-only), and enforce a character-online guard. A new launcher Playerbots page consumes typed Rust commands, one per verb, same thin fixed-argv pattern as every other page. Spec: `docs/superpowers/specs/2026-07-16-my-party-design.md` (approved; preflight-pinned on the live box 2026-07-16).

**Tech Stack:** bash + bats-core (stubbed SOAP/MySQL in `cli/tests/helpers/env.bash`), Lua (mod-ale/Eluna, hook `RegisterPlayerEvent(42,...)` = PLAYER_EVENT_ON_COMMAND), Tauri 2 + Rust (cargo fixture tests), Svelte 5 runes + SvelteKit, vitest, svelte-check.

## Global Constraints

- NEVER hand-edit `cli/dml` — it's built by `bash cli/build.sh` concatenating `cli/src/*.sh` in glob order (`00,10,20,30,40,50,90`; this plan adds `50-party.sh`, which sorts after `40-config.sh` and before `90-main.sh` so its helpers are defined before the `party)` arm uses them). Edit `cli/src/*.sh`, rebuild.
- The whole built CLI runs under `set -euo pipefail`. EVERY fallible command substitution must be guarded (`if out="$(cmd)"; then rc=0; else rc=$?; fi`, or `|| true`); every helper ending in a conditional ends with `return 0`. This bit prior plans repeatedly.
- JSON contract: every `--json` call emits exactly ONE envelope on stdout — `{"ok":true,"data":{...}}` or `{"ok":false,"error":{"code","message","hint"}}` + exit 1 — EXCEPT `party-setup`, which streams NDJSON like `games start/restart` (`section_start`/`line`/`section_end`/`done`/`error`). Error codes only from: UNKNOWN_COMMAND, NOT_FOUND, NO_COMPOSE, DOCKER_DOWN, START_FAILED, STOP_FAILED, SOAP_AUTH, SOAP_FAULT, SOAP_UNREACHABLE, DB_UNREACHABLE, BAD_ARG, MISSING_DEP.
- Never quote-wrap name/class args in AC console commands (AC's parser keeps quotes literal). Bridge commands are bare tokens: `dml_addclass <player> <class> [gender]`.
- Every value-taking flag calls `_need_flag_val "$1" $#` before reading `$2`.
- Class allowlist (lowercase, exactly these 9 — Death Knight omitted per spec): `warrior paladin hunter rogue priest shaman mage warlock druid`. Character/bot names: `^[A-Za-z0-9_]{1,12}$` (existing `_valid_charname`).
- **Bot-vs-human**: `characters.online=1` INCLUDES the ambient random bots (live-verified). Human players = accounts NOT flagged in `acore_playerbots.playerbots_account_type` with `account_type IN (1,2)` (1=RNDbot, 2=AddClass). `party online` MUST exclude bots; `party list` flags bots via the same table (fully-qualified cross-schema, same pattern as the `accounts` verb's `acore_auth.account`).
- **Pinned schema** (live-verified 2026-07-16): `group_member(guid=groupId, memberGuid, memberFlags, subgroup, roles)`; `characters(guid, account, name, race, class[tinyint 1-11], gender, level, online)`; `acore_playerbots.playerbots_account_type(account_id, account_type)`. A player's group: `SELECT guid FROM group_member WHERE memberGuid=<pguid>`. Class ids: 1 Warrior,2 Paladin,3 Hunter,4 Rogue,5 Priest,6 DeathKnight,7 Shaman,8 Mage,9 Warlock,11 Druid.
- **Eluna load**: no live Lua reload on this build (`.reload` has no eluna entry; `ALE.AutoReload=false`). ```lua
--[[ ============================================================
  dml_addclass.lua — Dad's MMO Lab "add a class-bot to my party" relay
  (AGPL-3.0, part of dads-mmo-lab; reimplemented from the behavioral
   reference, not copied.)

  Registers a console/SOAP-callable command:
      dml_addclass <playerName> <classname> [gender]

  Runs `.playerbots bot addclass <classname> [gender]` AS IF
  <playerName> typed it in-game. .playerbots requires a live player
  session (m_session->GetPlayer()), so it cannot be run from SOAP
  directly — Eluna's Player:RunCommand bridges a SOAP-triggered
  command into the player's own session.

  NB: the entry point is `.playerbots bot` (PlayerbotMgr's
  HandlePlayerbotCommand owns the `addclass` sub-keyword), so the
  command is `playerbots bot addclass <class>`, NOT the intuitive
  `playerbots addclass` which the chat framework rejects with USAGE.
============================================================ --]]

-- PLAYER_EVENT_ON_COMMAND = 42 (https://www.azerothcore.org/eluna/Hooks.html)
local function OnAddclassCommand(event, player, command)
    if player ~= nil then return end  -- console / SOAP origin only

    local pname, classname, gender =
        command:match("^dml_addclass%s+(%S+)%s+(%S+)%s+(%S+)$")
    if not pname then
        pname, classname = command:match("^dml_addclass%s+(%S+)%s+(%S+)$")
        gender = nil
    end
    if not pname then return end  -- not our command

    local p = GetPlayerByName(pname)
    if not p then
        print(string.format("[dml_addclass] player not found/offline: %s", pname))
        return false
    end

    local cmd
    if gender then
        cmd = string.format("playerbots bot addclass %s %s", classname, gender)
    else
        cmd = string.format("playerbots bot addclass %s", classname)
    end
    p:RunCommand(cmd)
    print(string.format("[dml_addclass] %s ran: .%s", pname, cmd))
    return false
end

RegisterPlayerEvent(42, OnAddclassCommand)
print("[dml_addclass] loaded -- addclass relay ready")
```

--[[ ============================================================
  dml_uninvite.lua — Dad's MMO Lab "kick a bot from my party" relay
  (AGPL-3.0, part of dads-mmo-lab; reimplemented, not copied.)

  Registers a console/SOAP-callable command:

    return false

# ---------------------------------------------------------------------------
# My Party (Plan 4): Eluna bridge deployment + group-join confirmation.
# Bridge scripts run playerbot commands in the online player's own session
# (SOAP -> Eluna hook 42 -> Player:RunCommand). See docs/.../my-party-design.
# ---------------------------------------------------------------------------

# Source dir of the committed bridge scripts (repo cli/lua/party). Resolved
# relative to this script's own location at build time is not possible in the
# concatenated artifact, so we resolve from the CLI's known repo layout via
# DML_LUA_DIR (test seam), falling back to the install-relative path.
_party_lua_src_dir() { echo "${DML_LUA_DIR:-/mnt/c/Users/perzi/dads-mmo-lab/cli/lua/party}"; }

# Host dir where mod-ale loads scripts (bind-mounted into the container at
# ALE.ScriptPath). <server dir>/env/dist/etc/modules/lua_scripts.
_party_lua_dest_dir() {
    local sdir="$1"
    echo "$sdir/env/dist/etc/modules/lua_scripts"
}

# Copy the 3 bridge scripts into dest; echo "changed" if any file's content
# differs from what's already there (idempotence), "" otherwise.
_party_deploy_scripts() {
    local src dest changed=""
    src="$(_party_lua_src_dir)"
    dest="$(_party_lua_dest_dir "$1")"
    mkdir -p "$dest"
    local f
    for f in dml_addclass.lua dml_uninvite.lua dml_login.lua; do
        if [[ ! -f "$dest/$f" ]] || ! cmp -s "$src/$f" "$dest/$f"; then
            cp "$src/$f" "$dest/$f"
            changed=1
        fi
    done
    [[ -n "$changed" ]] && echo changed
    return 0
}
```

    args: Vec<String>,
    on_event: Channel<serde_json::Value>,
    state: State<'_, AppState>,
