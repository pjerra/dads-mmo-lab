# QoL Batch — Design Spec (Round I)

**Date:** 2026-07-18 · **Branch:** `feat/dml-launcher-windows` · Design review waived. Shortlist item 5 (batched small wins). Dropped from scope: flush-random-bots (no console command exists in mod-playerbots — verified by source grep; the Lab's version likely truncates playerbots DB tables — needs dedicated research, deferred), ahbot one-click reload (no verified console command; Settings' restart flow covers conf changes).

## The six items

1. **Restart button (Home)** — UI only: `gamesRestart` command + wrapper already exist; Home gains a `Restart` button beside Stop (streams into the terminal like start/stop, same busy discipline). Two-step confirm NOT needed (same weight as stop+start).
2. **Reload ALE scripts (Settings)** — UI only: a button in the Config/Settings page's ALE area calling the existing `wowConsoleSend("reload ale")`; success note shows the console reply. (Verified command — it's the hint our own lua installer prints.)
3. **Teleport to coordinates** — `wow teleport-coords --char C --map M --x X --y Y --z Z --json`: OFFLINE-ONLY DB write of `characters.position_x/y/z/map` (+`orientation 0`): `_valid_charname` first; map `^[0-9]{1,3}$`; x/y/z `^-?[0-9]+(\.[0-9]+)?$` and |v| ≤ 20000; character must exist (NOT_FOUND) and be `online = 0` (`CHAR_ONLINE` error otherwise — teleporting an online char corrupts position). **This adds a third narrowly-sanctioned MySQL write** (position columns only, offline only) — the write-policy comment blocks in 30-db.sh/60-backup.sh get updated to name it. UI: a `Coordinates…` toggle on the Teleport page (map/x/y/z inputs + the char picker; client-side validation mirrors; note copy `Character must be logged out.`). The CLI's old `--coords` rejection stub on `teleport` is replaced by a hint pointing at `teleport-coords`.
4. **At-login flags (GM Tools)** — `wow gm at-login --player P --flag rename|customize|changerace|changefaction --json` → SOAP `.character rename P` / `character customize P` / `character changerace P` / `character changefaction P` (closed flag set validated before command build; works for offline chars — these console commands set the at_login flag). GM Tools gains an `At next login` card: char picker + flag select + Apply + two-step confirm (copy `Applies at that character's next login. Continue?`).
5. **Bot level control (Playerbots page)** — UI only: per-bot row gains a small level input (1-255) + `Set level` button calling the existing `wowGmLevel` (works offline; same command GM Tools uses). Confirm not required (non-destructive, reversible).
6. **Party preset export/import** — CLI: `wow party preset-show --name N --json` → `{name, classes:[...]}` (reads the preset file); `wow party preset-import --name N --classes "warrior,mage,…" --json` → validates name (`_valid_preset_name`) + each class against the existing class-name set (the same list `party add` accepts), writes the preset file (LF, one class per line; `EXISTS` error unless `--force`). UI (Playerbots presets card): `Export` per preset → modal/inline `<textarea readonly>` with the comma list (copy-by-hand); `Import` → name + comma-list inputs → preset-import (with `--force` after a two-step overwrite confirm when the name exists).
