## Guard 4 — the join nothing asserted

`yulon/ui/controller_view.py` builds a `purge.Uninstaller` twice, once per family
that has an Uninstall, and hands each one `image_refs=composegen.built_image_refs(
entry, server_dir)`. Those refs are the entire scope of the image removal: what
is not in them is not deleted, ever.

**The ground, measured at `dcc64543` before a line was written.** Replacing the
WotLK join (`:778`) with `image_refs=()` and running the whole suite:

| | result |
| --- | --- |
| unmutated | 5 failed, 3597 passed, 20 skipped, 23 deselected in 149.00s |
| `image_refs=()` at `:778` | 5 failed, 3597 passed, 20 skipped, 23 deselected in 146.84s |

Byte-identical, the same five failures both times — all five are the laptop's
own CRLF artefacts (`test_patch`, `test_extract`, two controller marker tests),
green on `yulon-fedora`. So every WotLK install's four images would have leaked
on every uninstall, for ever, with nothing red.

The same mutation at `:1128` (Vanilla) was caught at once, by
`test_uninstall_second_family.py::test_the_vanilla_uninstall_removes_this_installs_images_and_not_the_shared_one`.
That asymmetry is the finding: **the join is asserted per family, so it is
unasserted on every family that has not had a box yet**, and 8.9c and 8.9d will
each add a third and a fourth wiring of the identical five lines.

Two things kept it invisible. `test_purge.py::test_only_this_installs_own_four_image_refs_are_removed`
hands a `Recorder` refs the test file computed itself, so it proves the engine
removes what it is given; and the whole 8.9a section of `test_controller_view.py`
assigns `services.uninstall = fake`, so the real `for_entry()` is never asked
what it wired. `reviews check functions, not call sites`, exactly.

**The guard:** `test_purge.py::test_every_tab_that_offers_an_uninstall_is_handed_this_installs_own_built_images`
enumerates the catalog rather than naming a family, asserts the refs equal
`built_image_refs()` for every entry that offers an Uninstall, asserts they are
non-empty and all `yulon.local/`, asserts this entry's PULLED database image is
not among them, and finally pins the subject: `["wow-vanilla", "wow-wotlk"]`
today, so the day 8.9c wires TBC this goes red and the fix is to add an id.

**The mutation the crashed lane left behind: there was none.** `dcc64543`'s
message says it did not take that hunk, and this lane confirmed it rather than

`yulon/ui/controller_view.py` at `dcc64543`, and `mutations.txt` records the
