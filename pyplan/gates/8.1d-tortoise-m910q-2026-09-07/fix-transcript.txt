8.1d's defect: the fix, proved on m910q
=======================================

The defect, from this folder's README: a Dashboard that has seen a restart loop
keeps calling it one after the container is recreated. Fixed at 44838184; what
follows is the same probe run against the code before and after, and then
against the real Tortoise worldserver.

Code: ~/gate81d at 44838184 (the 'before' run has dashboard.py alone checked out
at 9eb0f63a, the commit before the fix).
Venv: ~/gate81d/pylauncher/.venv-gate (Python 3.11.15).


1. THE MECHANISM, on a stand-in container  (dashprobe.py)
--------------------------------------------------------

A busybox container named dash-probe, put into a real restart loop under
'--restart unless-stopped', then replaced. Chosen over the worldserver on
purpose: what is in question is docker's own bookkeeping across a replacement,
and busybox answers it in forty seconds where a worldserver costs minutes of
map loading.

    Note what compose said: 'Container tortoise-mangosd Started', not
    'Recreated' - and RestartCount still went 8 -> 0. A manual start resets
    docker's count, which is why the count going BACKWARDS is the evidence the
    fix reads, and why the ten-minute settle rule could not cover this on its
    own.

    Screenshots: 5-restart-loop-on-the-tab.png (verdict 'restart loop - 8
    restarts, this run up 5s', status 'db down, auth up, world up') and

    Start greyed out because the server is running). Both are the Server tab
    drawn offscreen with this watcher behind it.

    The bot count climbing 0 -> 118 -> 123 across the last polls is this
    server's own bots logging back in, not a reading that drifted.
