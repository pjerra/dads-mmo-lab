WHAT THE LISTENER ACTUALLY SPEAKS  (soapprobe.py)
-------------------------------------------------

The CMaNGOS source study stopped exactly here and said so: the envelope lives
in generated code it did not read, and "a caller-side decision needs either
that file read or a live probe". This is the live probe. Three envelope shapes,
each sent with the right credentials and with wrong ones.

    urn:AC (what the app sent) / the real password
        HTTP 500  faultstring: Method 'ns1:executeCommand' not implemented:
                  method name or namespace not recognized
    urn:AC / a wrong password
        HTTP 500  the same fault - the namespace is checked BEFORE the password
    urn:MaNGOS / the real password
        HTTP 200  <result>CMaNGOS/0.18 ... Online players: 0 (max: 0)
                  Server uptime: 5 Minute(s) 6 Second(s).</result>
    urn:MaNGOS / a wrong password
        HTTP 401  faultstring: Error 401: HTTP 401 Unauthorized
    no namespace / either password
        HTTP 500  Method 'executeCommand' not implemented

So a wrong namespace is INDISTINGUISHABLE from a world that has not finished
loading, which is exactly how it presented: three Pending attempts and a GaveUp.


WHAT THE APP'S OWN SEAM MAKES OF THOSE  (answerprobe.py)
--------------------------------------------------------

    the right password   soap.Reply.outcome 'answered'  Answer.outcome 'yes'
                         Answer.denied False
    a wrong password     soap.Reply.outcome 'unauthorised'
                         Answer.outcome 'unknown'  Answer.denied True

`denied` was already there and correct; nothing was reading it in the setup
path. That is the defect this gate found.

The CONF is what makes this clause different here. On WotLK the rollback undoes
an override and gives a port back; on this tree it also has to put `SOAP.Enabled`
back to 0, because the world reads that file on the way up and a rolled-back
channel that still said 1 would bind a port it had just been told to release.
