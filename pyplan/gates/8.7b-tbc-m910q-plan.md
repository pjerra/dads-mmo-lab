# 8.7b live gate — TBC modules on m910q

**Definition of done being proved:** *at least one manifest installs and its key is reported
by the running server after the restart it asks for.*

The manifest that proves it is **`motd`**. It is the only item in the set whose effect the
server states back on its own console: `.server motd` runs
`ChatHandler::HandleServerMotdCommand` → `PSendSysMessage(LANG_MOTD_CURRENT, sWorld.GetMotd())`
(`src/mangos-tbc/src/game/Chat/Chat.cpp:816`, `Level0.cpp:281`, read on m910q 2026-09-08), and
`allowConsole` is true in that command table row, so it answers from the mangosd console with
no client and no logged-in character. Every other item is proved by reading the file or the
database — real, but not "reported by the running server".

Evidence goes in `pyplan/gates/8.7b-tbc-m910q-<date>/`, one file per step, named below.

### Preconditions the runner must satisfy before step 1

1. **Nothing else is running a server on m910q.** Owner rule: one server at a time. At plan
   time the **Tortoise** stack was up and another lane held the box. Do not start TBC beside
   it. Either that lane has finished and stopped its stack, or this gate stops it
   (`docker compose -f ~/tortoise-server/docker-compose.yml stop`) and restarts it afterwards —
   and says which, in `00-preconditions.txt`.
2. `~/tbc-7.4c/etc/mangosd.conf` is **copied aside** to
   `~/tbc-7.4c/etc/mangosd.conf.before-8.7b` and its `sha256sum` recorded. This gate writes to
   that file. The box already carries a `mangosd.conf.before-channel` from an earlier lane, so
   the current file is NOT assumed to be the shipped one — which is exactly why the checksum,
   not a diff against upstream, is the reference.
3. This branch is checked out on the box (the manifests and `controller_wow_tbc/modules.py`
   ship with it). `python -c "from yulon.controller_wow_tbc import modules"` must import.
4. Announce every step with `~/claude-say` before running it.

## The steps

Each step names the clause it proves and the ground it starts from. A step that fails stops
the gate; the definition of done is not partially met.

### 1 — the app can see this game's manifests at all
*Clause: "a manifest set … for this game".* Ground: a checkout, no containers needed.

```
python - <<'PY'
from yulon.controller_wow_tbc import modules as m
for x in m.store().load_all("mod"):
    print(x.id, x.type, x.game, "rebuild=%s" % x.build.rebuild, "restart=%s" % x.build.restart)
PY
```
Expect five rows, all `wow-tbc`, all `rebuild=False restart=True`.
→ `01-manifest-set.txt`

### 2 — the binding, through the shipped path and not a hand-built applier
*Clause: "and binding".* Ground: server dir on disk, containers still down.

Build the services the Server tab builds, and read back what the tab would hold. This is the
path a user's press takes; a hand-made `Applier(server_dir, sql=...)` here would prove the
engine and not the wiring.

```
python - <<'PY'
from pathlib import Path
from yulon.catalog.catalog import load_catalog
from yulon.ui.controller_view import ControllerServices
e = load_catalog().get("wow-tbc")
s = ControllerServices.for_entry(e, Path.home() / "tbc-7.4c")
print("has_manifests", e.has_manifests)
print("store game   ", s.store.game)
print("applier root ", s.applier.server_dir)
print("sql schemas  ", dict(s.applier.sql.schemas))
print("sql client   ", s.applier.sql.client, "container", s.applier.sql.db_container)
PY
```
Expect `store game wow-tbc`, `world` → `mangos` (**not** `acore_world`), client `mariadb`,
container `tbc-db`. Needs `QT_QPA_PLATFORM=offscreen` if the venv's PySide6 wants a display.
→ `02-binding.txt`

### 3 — the server is up, and the Motd it has now is recorded
*Clause: the "before" half of "reported … after the restart".* Ground: preconditions done.

Start the stack the way the app does (`docker compose up -d`), wait for `Avg Diff:` in the
mangosd log (up to 1800 s — a CMaNGOS world load with 500 bots is not quick), then ask the
console:

```
python - <<'PY'
from yulon.controller_wow_tbc import console
r = console.send_command(".server motd")   # container defaults to tbc-mangosd
print(r.prompted, r.lines)
PY
```
Record the answer. This is the value step 6 must have replaced, and step 8 must have restored.
→ `03-before-motd.txt`, `03-mangosd-ready.log`

### 4 — install the manifest, through the applier from step 2
*Clause: "at least one manifest installs".* Ground: server running, conf as in step 0.

```
python - <<'PY'
from pathlib import Path
from yulon.catalog.catalog import load_catalog
from yulon.controller_wow_tbc import modules as m
from yulon.ui.controller_view import ControllerServices
e = load_catalog().get("wow-tbc")
s = ControllerServices.for_entry(e, Path.home() / "tbc-7.4c")
r = s.applier.install(m.store().load("mod", "motd"), {"motd": "Yulon 8.7b gate"})
print(r)
PY
```
Expect `done=('set 1 key(s) in etc/mangosd.conf',)`, `skipped=()`, `rebuild_required=False`,
**`restart_recommended=True`** — that last is the clause "the restart it asks for", and it is
the field `Build.restart` was added for.
→ `04-install-report.txt`

### 5 — the file changed, and only in the one line
*Clause: the install is a real edit, not a report about one.* Ground: step 4 ran.

`diff etc/mangosd.conf.before-8.7b etc/mangosd.conf` — expect exactly one changed line,
`Motd = "Yulon 8.7b gate"`. A second changed line means `_set_conf_key`'s regex caught
something it should not have.
→ `05-conf-diff.txt`

### 6 — the running server still reports the OLD value
*Clause: this is what makes the restart load-bearing rather than decorative.* Ground: step 5.

`.server motd` again, **without** restarting. Expect the step-3 value. If the new one appears
here, mangosd is re-reading the conf and `build.restart` is over-claiming — record that, it is
a finding about the manifest, not a gate failure.
→ `06-before-restart-motd.txt`

### 7 — restart, then the server reports the NEW value
*Clause: **"its key is reported by the running server after the restart it asks for"** — the
definition of done.* Ground: step 6.

Restart mangosd through the app's own controller (`TbcController.stop()` then `.start()`, or
`docker compose restart tbc-mangosd`; whichever, say which in the file). Wait for `Avg Diff:`
again — up to 1800 s, and `stop_grace_period` is 5 m, so budget the shutdown too. Then:

```
python - <<'PY'
from yulon.controller_wow_tbc import console
r = console.send_command(".server motd")   # container defaults to tbc-mangosd
print(r.prompted, r.lines)
PY
```
**Expect `Yulon 8.7b gate`.** That line, next to step 3's and step 6's, is the whole gate.
→ `07-after-restart-motd.txt`, `07-restart.log`

### 8 — remove puts it back, and the file is byte-identical again
*Clause: the manifest is reversible, which is what makes it safe to ship.* Ground: step 7.

`s.applier.remove(<the motd manifest>)`, then `sha256sum etc/mangosd.conf` against step 0's.
The remove patch writes CMaNGOS's shipped default line, so the two match only if the file
started at that default — if the box's Motd had been edited before this gate, the checksums
differ **by design**, and the honest record is the diff plus a manual restore from
`mangosd.conf.before-8.7b`.
→ `08-remove-report.txt`, `08-conf-sha.txt`

### 9 — one SQL mod, end to end
*Clause: "a module is a CONFIGURATION ACTIVATION **or a SQL MOD**". Ground: server running.*

`all-stackables` is the SQL half. Its proof is a query, not a console line — say so in the
file rather than implying the server reported it.

```
docker exec tbc-db mariadb -uroot -p"$(cat ~/tbc-7.4c/.db_password)" -N -B mangos \
  -e "SELECT COUNT(*) FROM item_template WHERE stackable > 1"
```
before; install with `{"stack_size": "200"}`; then
`SELECT COUNT(*) FROM item_template WHERE stackable = 200` — expect the first count. Then
`remove`, and the first query must give the first count again with
`yulon_stackable_backup` gone. Restarting mangosd afterwards must still reach `Avg Diff:`
(the item_template load must not complain about the new values) — that is the running
server's only word on this one, and it is worth having.
→ `09-sql-mod.txt`

### 10 — leave the box as it was found
Stop the TBC stack (`docker compose stop`), confirm `docker compose ps` is empty, restore the
Tortoise stack if step 0 stopped it, and delete any scheduled task this run created.
→ `10-teardown.txt`

## What this gate does NOT prove, and should say so

* **The Modules tab as a widget.** Steps 2–8 drive `ControllerServices`, which is the object
  the tab holds, but not the button press. `test_controller_view.py` covers the press.
* **`xp-rates`, `all-flight-paths`, `cross-faction`.** They are the same mechanism as `motd`
  against different keys, and the unit tests prove each writes and restores its own set. If
  the gate has budget, `cross-faction` is the one worth adding: it is nine keys and nine
  remove patches, and it is where a missing pair would show.
* **That a player sees the effect.** No client is driven. `.server motd` is the server's own
  answer about its own state, which is what the clause asks for.
