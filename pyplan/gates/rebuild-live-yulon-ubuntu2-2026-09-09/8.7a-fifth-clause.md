# 8.7a's fifth clause, answered by this rebuild

`pyplan/gates/8.7a-wotlk-yulon-ubuntu-2026-09-08/README.md` reports four of five clauses passed and
the fifth **NOT MET**, blocked on the rebuild the owner runs:

> *a configuration change the module needs is shown by the running server, not only read back from
> the file*

and it measured why, on `yulon-ubuntu`, rather than guessing: AzerothCore looks module conf files up
by the names of the modules **compiled into the binary** (`Acore::Module::GetEnableModulesList()`),
so a module that has not been compiled in has no name on that list and its conf file is invisible
however correct it is. Its ground was:

```
List of enabled modules:
|- mod-playerbots

Loading Modules Configuration...
> Config::LoadFile: Failed open file '/azerothcore/env/dist/etc/modules/playerbots.conf'
> Not found modules config files
```

**After the rebuild on `yulon-ubuntu2`, the same server, asked the same way** (the app's own command
channel, `9-clause5-server-debug.txt`, screenshot `6-running-server-names-mod-ale-and-its-conf.png`,
`ac-worldserver running pid=98208 restarts=0`):

```
List of enabled modules:
|- mod-ale
|- mod-playerbots
```

and in the world server's own startup log, in its own words:

```
Loading Modules Configuration...
> Config::LoadFile: Failed open file '/azerothcore/env/dist/etc/modules/playerbots.conf'

Using modules configuration:
> mod_ale.conf
```

The running server **names the module** and **names the conf file it opened**. Two of that file's
values are then shown by what the server did rather than by reading the file back:

* `ALE.Enabled = 1` — the engine ran at all;
* `ALE.ScriptPath = "/azerothcore/env/dist/etc/modules/lua_scripts"` — it loaded the five scripts
  that are in exactly that directory, and named each one.

**The clause is met on this box, for a module that has been through a rebuild.** Two honest limits on
that, and they are why this file does not tick anything:

1. It is met for `mod-ale`, on `wow-wotlk`, on `yulon-ubuntu2`. 8.7a's own run was against
   `mod-npc-beastmaster` and `mod-1v1-arena` on `yulon-ubuntu`, and those two are still not compiled
   into any binary — their conf files are still invisible to their server for the reason 8.7a
   measured. Nothing here says otherwise.
2. `playerbots.conf` is **still** missing from the same log line, exactly as 8.6 recorded: that
   module's conf ships as a `.dist` this install never activates, so mod-playerbots runs on its
   compiled defaults. The rebuild changed nothing about that, and the line above is evidence the
   reading works rather than evidence of a second failure.

Ticking 8.7a is the owner's session's job and this lane has not touched `pyplan/checklist.md`.
