## Review 1 (Codex adversarial, 2026-09-09 15:15) -- REWORK, two design findings

- [high] Existing installations never execute the new phase: `MarkerGate` classifies any existing marker, including one with an older plan hash, as `imported`, and the import stage then skips every phase -- so an established Tortoise install still missing `character_inventory_copy` stays exposed to the calendar crash the ticket names. The four tests inspect and expand the plan; none upgrades an older marked install. Recommendation: an explicit upgrade route for installs carrying the old marker, with a test starting from the previous marker.
- [medium] The glob delegates future migration safety to the fork: every future `character_updates/*.sql` is imported, the idempotence argument covers the three files present today, imports are not per-file checkpointed, so a retry replays earlier files and a later non-idempotent file can wedge fresh installs with no launcher change and no failing test. Recommendation: an audited allowlist, or a per-file ledger, and validation of newly matched files at fork sync.
