## The findings

1. **Prefix, not line.** `_look()` decides OURS by `startswith("# generated by Yu'lon")`. A file whose first line is `# generated by Yu'lon-custom` or `# generated by Yu'lon (modified)` — a user marking a file they took over — is replaced wholesale at rebuild, against T8's contract ("still carries the line Yu'lon wrote at its top"). The refusal test deletes the marker outright, so the prefix mutation survives. `generate-compose` applies the same prefix rule to compose files.
2. **Touched before touching.** The `recreate` wrapper sets `touched = True` and then calls `stage_recreate()`. When recreate raises before any container is replaced (daemon connection refused, compose validation), the exception path skips `_put_recipe_back()` because `touched` already reads true, and takes the rollback arm's second recreate for nothing — the rendered Dockerfile and `.dockerignore` stay on disk while the old server was never replaced. The existing stop test cancels before the wrapper is entered.

## What to build

- One first-line comparison, exact: the first line equals the marker (line terminator excepted), used by `_look()`, the render-time check, and `generate-compose`. Tests for both files with the two prefix variants above: THEIRS, refusal, no compile, no write; the mutation is `startswith`.
- `touched` becomes true at the first confirmed destructive step, not on entry: either `stage_recreate` yields a marker line / sets a flag when the compose command that replaces the container has been issued, or the wrapper splits validation from mutation. Test: recreate raises before touching -> both recipe files restored byte for byte, the stage state restored, no second recreate; the mutation is the old placement. Keep the existing rollback tests green (a recreate that fails AFTER replacement still rolls back).
