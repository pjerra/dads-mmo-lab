## Why

Exit clause 6 (`checklist.md:2508`) says Phase 7's cross-server regression pass re-runs green on the merged tip. 7.10 is 52 of 53 (`pyplan/gates/7.10-rerun-ubuntu2-2026-09-09/widget-run.log:61`, `:126`). The one FAIL is a clause that **cannot fail when the row happens to hold the LAN address**, and could not have passed last night for the opposite reason:

`drivers/widget_driver.py:296-306` reads `acore_auth.realmlist.address` from the database and asserts that string appears in the plan text the Networking tab shows. `network_plan('lan')` **proposes** this box's LAN address (`172.30.48.189`); the row **holds** whatever was last applied (`100.99.204.5` last night, put there so the owner's client can reach the VM through the Hyper-V host). On 09-04, 09-05 and 09-08 the two were equal only because the row held the LAN address, so for three runs the clause compared the plan to itself. The audit's finding, verbatim: *"correct that clause to compare the plan text against `plan.lan_ip`, and assert separately that `network_apply` writes it into the row — the material for the second half is already measured in `sweep4.log`."*

## What to change

1. **The proposal half**: the plan text must name `plan.lan_ip` — the address the widget's own `network_plan('lan')` computed — not whatever the row holds. Read how the driver gets the plan object (it already prints `plan_text`) and compare against the object's own field.
2. **The apply half, separately**: `sweep4.log:7-15` already measures `network_apply('lan')` → `realmlist → 172.30.48.189` and the `UPDATE acore_auth.realmlist SET address=…` it ran. Either cite that measurement from the corrected clause's comment (say which line) or add a clause in the widget driver that reads the row **after** an Apply and asserts it equals `plan.lan_ip`. If you add one, it must read its ground (the row BEFORE the apply) and refuse to run if the ground already equals the plan — a clause true before its action is the defect this whole round exists to repair.
3. **Prove the corrected clause can fail**: make the plan and the row disagree deliberately (set the row to a different routable address with the app's own tooling or one `UPDATE`, read it back), run the clause, show it FAILS, restore, show it PASSES. Both runs in the evidence.
4. **Re-run the widget half of 7.10** — all 33 widget clauses, not a subset — on `yulon-ubuntu2` with the corrected driver, and report the score. If it is not 33 of 33, that is the answer; do not adjust another clause to make it pass.
