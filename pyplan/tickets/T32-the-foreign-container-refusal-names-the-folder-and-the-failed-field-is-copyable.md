## What the code says (lead's Phase 1, without the log)

- The sentence comes from `native.py:4097-4101`, `_refuse_foreign_containers()`, which `run()` calls once through `_guard()` at the start of a run (`native.py:2184`, `:3949`) — never after a stage. So the screenshot is a **second run** meeting containers a previous run made.
- "Another install" is `owner != ours` where `owner` is the container's `com.docker.compose.project` label (`docker.container_project()`) and `ours` is `composegen.project_name(entry.id, server_dir)` — SHA-256 of the folder's absolute path. The `install_id` argument the method receives is unused, but that is not a defect: `_claim_folder()` (`native.py:4015-4020`) already refuses a folder whose state file carries a different id, with its own sentence, before the guard runs. So when this sentence appears the folder's identity is intact and the containers were made from a **different folder** — the reporter's first, still-running install — and the app refused correctly. The reporter could not know that, because the refusal names a project id (`yulon-wow-wotlk-db937032`) and not the folder, although `docker.container_working_dir()` (`docker.py`, beside `container_project()`) already reads the label that holds it.
- The label carrying the refusal is `LogPanel._status`, a `QLabel` created at `log_panel.py:204` with no text-interaction flags: on every platform the text cannot be selected, so a report arrives as a screenshot.

## Definition of done

**Half A — the refusal names the folder.** `_refuse_foreign_containers()` asks `self._seams.container_working_dir(name)` (add the seam beside `container_project` in `native.Seams`, defaulting to `docker.container_working_dir`, threaded like the others) and the sentence becomes, for a project whose name starts with `yulon-`: `A container called {name} already exists and belongs to another install this app made, at {working_dir}. Two servers cannot share that name. Open that install's tab and stop and remove its containers, or install into {working_dir} instead.` For a project without the prefix: `…belongs to another Docker Compose project ({owner}), brought up from {working_dir}…` (keep the existing tail). When the working dir reads `None` or `UNREADABLE` the sentence says the folder could not be read and still names the project. The `yulon-` prefix is `composegen.project_name`'s own literal — bind them with one constant and a test that the refusal's prefix and `project_name()`'s prefix are the same string. Tests: the three answers of the working-dir seam (a path, `None`, `UNREADABLE`) each produce the sentence above, each with its named mutation; the existing foreign-container tests keep passing; `support_native.py`'s fake seams gain the new answer.
