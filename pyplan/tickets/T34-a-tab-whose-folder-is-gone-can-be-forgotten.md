## What the log and the code say

- `yulon.log` on the box, 22:38:17 — the owner's press of "Stop and remove containers…": `docker could not be started: [WinError 267] The directory name is invalid`, then `could not resolve ac-worldserver in C:\Users\pk\wow test install\wow-server-playerbots: Docker could not be found on this machine. Install Docker Desktop…`, then `stop_staged(): no project name, and nothing running under our names`. Docker Desktop was running the whole time. `docker._docker()` (`docker.py:~196-225`) runs the CLI with `cwd=server_dir`; when that folder does not exist `subprocess` raises `OSError` (WinError 267 on Windows, `FileNotFoundError`/`NotADirectoryError` on POSIX) and the `except OSError` branch reports it as the "no docker CLI" sentinel (`_CLI_MISSING_RETURNCODE` + `DOCKER_CLI_MISSING_HELP`). The user is told to install Docker.
- Uninstall: `purge.Uninstaller._resolve()` asks ownership first — `_claim(server_dir)` reads the folder's install record; with no folder that answers `UNCLAIMED` and `refusal_for()` says `Nothing here says Yu'lon installed it: there is no install record in {dir}, so this folder is not Yu'lon's to delete. Nothing was removed.` The Uninstall label shows it and the confirm button stays hidden (`controller_view.py:3269-3276`). Correct as a refusal to delete — and a dead end: the only way to drop the record is `state.forget()`, which no button on the tab reaches (the "Forget that record" button at `controller_view.py:4564` is the Maintenance tab's interrupted-restore control).

## Definition of done

**Half A — a missing working directory is named, not misreported.** In `docker._docker()` (and the two sibling launch sites at `docker.py:~3216` and `~4019` if they take a `cwd`), when `cwd` is given and `not cwd.is_dir()` the call does not run the CLI and does not produce the CLI-missing sentinel; it returns a `CompletedProcess` with a distinct non-zero code and a stderr sentence: `The server folder {cwd} no longer exists, so Docker was not asked.` — and `_cli_missing()` must be False for it. Callers that turn stderr into the user's sentence (`could not resolve …` at the `stop_staged` path, `container_state` reads) then carry that sentence. Tests: a `cwd` that does not exist yields that sentence and not `DOCKER_CLI_MISSING_HELP` (mutation: drop the `is_dir()` check → the CLI-missing text comes back); the existing "no CLI at all" test still passes; the `WinError 267` shape recorded in the docstring in one past-tense paragraph.

**Half B — Forget this install.** On the Server tab, beside "Uninstall…", a button `Forget this install…` that is **visible only when `server_dir` does not exist** (re-evaluated on the same poll that sets the status line — the folder can be deleted while the tab is open). Press → `QMessageBox.question` through `said_yes()` (T33's helper; if T33 has not merged yet, compare with `==`) with the text: `{server_dir} no longer exists. Forget this install? Yu'lon removes only its own record of it — the tab closes and the Catalog offers the game again. Any Docker containers, volumes or images named for it are NOT touched, because without the folder Yu'lon cannot prove which ones were its own; remove those from Docker Desktop yourself if they remain.` Yes → the tab's persisting forget seam (the same `forget` the Uninstaller is handed by `main.py`, so the live `AppState` is used, not a re-load — read `forget_record()`'s docstring at `controller_view.py:690`) → `uninstalled` emitted so `main.py` drops the tab exactly as after an uninstall. No → nothing. Uninstall's own refusal sentence for a missing folder gains one clause: `… Nothing was removed. If the folder is gone for good, "Forget this install…" drops this tab.` Tests in `test_controller_view.py`: the button hidden while the folder exists, shown when it does not; the press with an int-returning fake Yes forgets and emits `uninstalled` with the game id and dir; No forgets nothing; a `forget` seam that raises `OSError` shows the error and keeps the tab. Mutations named per test.
